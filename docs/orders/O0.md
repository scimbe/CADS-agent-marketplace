# O0: tests/net.rs scheitert im Debug-Build — Ursache belegen, dann beheben

Repo: cads-agent-marketplace, Branch feat/phase2-blueprints, Crate blueprints/collab-crdt.

## Befund (belegt)
`cargo test -p bp-collab-crdt --test net editors_on_a_relay_tree_over_tcp_converge_to_the_oracle`:
- `--release`: 3 von 3 Läufen grün.
- Debug: 2 von 3 Läufen rot, „2 of 120 editors differ from the oracle“ bzw. „10 of 120“.

Hypothese (nicht belegt): Ein Editor beendet sich, sobald seine eigene Outbox 1,5 s leer ist, ohne zu wissen, ob er alle
fremden Schreibvorgänge hat; Editoren, die nach `stop` noch aus einer Offline-Phase zurückkehren und nachsenden, erreichen
ihn dann nicht mehr. Ebenso möglich: eine echte Lücke in Relay/Leaf/Client unter Last (z. B. Lagged-Nachlieferung,
Wiederverbindung des Leaf, Chunking der Nachlieferung).

## Auftrag
1. Ursache belegen (z. B. pro abweichendem Editor: welche Register fehlen, wer schrieb sie, wann; ob sie im Root-Log liegen).
2. Ist es das Testende: den Test so beenden, wie ein Prüfer es muss — erst wenn *alle* Editoren fertig gesendet haben und
   danach jeder Editor den Stand des Roots erreicht hat (z. B. gemeinsamer Abschluss: alle Outboxen leer, dann jeder bis zur
   finalen Root-Sequenz nachgezogen). Ist es das Protokoll: das Protokoll beheben (src/net.rs) und einen Test, der genau
   diesen Fall erzwingt.
3. Keine Schwelle lockern, keine Editorenzahl senken, kein `#[ignore]`.
